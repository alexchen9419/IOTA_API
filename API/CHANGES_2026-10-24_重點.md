# API 修改重點（2026-10-24，未 commit）

完整版：`CHANGES_2026-10-24.md`。只含 `API/`，App 未改。

## 1. 門鈴／防拆推播

- 裝置按門鈴、被拆時，`api-mqtt-bridge` 轉成警報 → `alert-service` 推給 App（MQTT）＋ Telegram／ntfy
- 防拆另外記成 UC4.4 安全異常（`DEVICE_TAMPERING`）
- 同裝置同事件 30 秒內只推一次（防洗版）
- 修掉舊 bug：`alert_service` 原本寫死連 1883，正式環境連不上
- 新增檔案：`common/push_notify.py`

## 2. 訪客 QR

- **舊**：建訪客帳號、QR 網址帶明文密碼——而且訪客帳號根本開不了門
- **新**：發 `guest_tokens` 通行碼（DB 只存雜湊），QR 開 `/guest` 訪客頁直接按開門
- 可限定裝置、期限、次數、開始時間
- 開門紀錄不再存明文 token
- 新增：`POST /guest_access`、`GET /guest` 訪客頁

## 3. 撤銷訪客授權

- 撤銷邏輯沒改，只是**之前沒掛路由，現在打得到** `POST /revoke_guest_token`
- 新增 `POST /list_guest_tokens`：Admin 查授權清單，拿 `token_id` 才能撤銷
- QR 改發 token 後，撤銷才真的能讓 QR 失效

## 部署前要做

1. 既有 DB 補欄位（新建的 DB 不用）：`docker exec -i iot_mysql mysql -uroot -pdevroot123 devicemanagement < API/migrations/2026-10-24_guest_tokens_valid_from.sql`（可重複執行）
2. 推播：repo 根目錄 `.env` 已建好，ntfy topic 已填；Telegram 要的話自己填 `TELEGRAM_BOT_TOKEN`／`TELEGRAM_CHAT_ID`
3. 訪客對外使用：`.env` 填 `GUEST_QR_BASE_URL`（HTTPS）

## 注意

- 舊版 App 仍可產生 QR，但帳密欄位會空白、沒有撤銷畫面、預設期限會提早 8 小時（舊問題）
- 全部只做過離線測試，**未在 Docker、實機上驗證**
- 動到的敏感範圍：`gateway.py`（加路由）、`control_device.py`（訪客 token 檢查）
