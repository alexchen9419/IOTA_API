## 2. 訪客 QR 改版

### 2.1 為什麼改

- 舊版建立的 `guest_xxx` 帳號**根本開不了門**：`control_device.py` 的帳號驗證只放行 Admin / Member。
- 明文密碼放在 QR 網址的 query string，會留在瀏覽器歷史、伺服器 access log 與 Referer。
- `control_device.py` 原本就支援 `auth_type=guest_token`（期限、次數、撤銷、限定動作與裝置），只是沒人發 token。

### 2.2 新流程

```
App (Admin)                    API                                  訪客手機
───────────                    ───                                  ────────
POST /generate_guest_qr ──►  寫 guest_tokens（只存 SHA-256）
                        ◄──  control_url = <base>/guest#t=GUEST_xxx
顯示 QR ─────────────────────────────────────────────────────────►  掃碼開 GET /guest
                                                                    （token 在 # 後面，不會送到伺服器）
                             POST /guest_access  ◄────────────────  查可開的門、剩餘次數
                             POST /control_device ◄───────────────  按「開門」
                               auth_type=guest_token, action=UNLOCK
POST /list_guest_tokens ──►  列出授權
POST /revoke_guest_token ─►  撤銷
```

### 2.3 端點變更

#### `POST /generate_guest_qr`（行為變更）

Request：

```json
{
  "family_id": 12,
  "admin_uid": "admin001",
  "device_id": "E8:31:CD:82:80:C8",
  "start_time": "2026-10-24T10:00:00Z",
  "end_time": "2026-10-24T14:00:00Z",
  "max_uses": 3
}
```

- `device_id` 選填（新增）：指定則只能開這台；不給 = 該家庭所有裝置。指定的裝置必須屬於該家庭，否則 404。
- `end_time` 與 `max_uses` 至少給一個。只給次數時，期限預設 `GUEST_QR_DEFAULT_HOURS`（預設 24）小時後。
- **時間不帶時區時當台灣時間（+08:00）**，建議一律帶 `Z` 或時區。
- `start_time` 晚於現在（未來才生效）需要 DB 有 `guest_tokens.valid_from`，否則回 500。

Response（`data` 欄位變更）：

| 舊欄位 | 新欄位 |
|---|---|
| `user_id`、`password` | 移除 |
| `mqtt_published` | 移除（不再發 `auth_sync` MQTT） |
| `authorization_id`（`QR_...`） | `authorization_id`（`GT_YYYYMMDD_...`，即 `guest_tokens.token_id`） |
| `control_url`（佔位網域 + `?uid=&pwd=`） | `control_url`：`<base>/guest#t=GUEST_...` |
| `start_time`、`end_time`（台灣時間字串） | UTC，帶 `Z` |
| — | 新增 `device_id`、`allowed_actions`（固定 `["UNLOCK"]`） |

`max_uses` 不限次數時回 `null`；DB 存 `2147483647`（`common/guest_token_limits.UNLIMITED_USES`）。

`control_url` 的 base：`GUEST_QR_BASE_URL` 有設就用；沒設用 App 打進來的 host（`http(s)://<host>/guest`），只限同區網。

Ledger 事件 `UC3.4_GUEST_TOKEN_ISSUED` 的 `credential_kind` 由 `GUEST_ACCOUNT_QR` 改為 `GUEST_TOKEN_QR`，`policy_enforced_by` 由 `GATEWAY` 改為 `SERVER`，帶 `token_hash`。

**不再寫入** `users`、`user_families`（不再建立或重用訪客帳號）。

#### `POST /guest_access`（新增）

訪客頁用。只讀、不扣次、不寫稽核。

```json
// Request
{ "guest_token": "GUEST_..." }

// Response
{
  "status": "Success",
  "data": {
    "family_id": 12,
    "expires_at": "2026-10-24T14:00:00Z",
    "remaining_uses": 3,
    "allowed_actions": ["UNLOCK"],
    "devices": [{ "device_id": "...", "device_name": "...", "device_type": "..." }]
  }
}
```

token 無效時的錯誤碼與 `control_device` 一致（見 2.4）。

#### `POST /list_guest_tokens`（新增）

僅家庭 Admin。不回 `token_hash` 或明文 token，不寫稽核。最多回 100 筆。

```json
// Request
{ "family_id": 12, "admin_uid": "admin001", "include_inactive": false }
```

每筆：`token_id`、`status`、`device_id`、`device_name`、`valid_from`、`expires_at`、`used_count`、`max_uses`、`remaining_uses`、`created_by`、`created_at`、`revoked_at`、`revoked_by`（時間皆 UTC 帶 `Z`）。

`status`：`ACTIVE`、`PENDING`（未生效）、`EXPIRED`、`USED_UP`、`REVOKED`。`include_inactive=false` 只回 `ACTIVE`、`PENDING`（可撤銷的）。

#### `POST /revoke_guest_token`（新掛路由）

腳本原本就存在，這次才掛進 `gateway.py`。邏輯只改剩餘次數改用共用函式。

```json
{ "token_id": "GT_...", "operator_user_id": "admin001", "family_id": 12, "reason": "..." }
```

#### `GET /guest`（新增）

回傳 `guest_page/guest.html`。標頭 `Cache-Control: no-store`、`Referrer-Policy: no-referrer`。頁面從 URL fragment 讀 token，呼叫 `/guest_access` 與 `/control_device`。

### 2.4 `control_device.py` 變更

- 訪客 token 檢查抽成 `find_valid_guest_token()`（撤銷 / 生效 / 到期 / 次數，不扣次），`guest_access.py` 共用；家庭、裝置、動作範圍檢查留在 `verify_guest_control()`。
- **新增檢查**：`valid_from` 晚於現在 → `403 TOKEN_NOT_YET_VALID`。
- **稽核遮蔽**：寫入 `audit_logs`、`control_commands` 的 request 副本把 `guest_token` 換成 `<redacted>`。原本明文 token 會永久留在雜湊鏈裡。
- 上鎖 / 開鎖、使用者授權、維修模式等流程未改。

訪客 token 錯誤碼：`MISSING_GUEST_TOKEN`、`TOKEN_NOT_FOUND`、`TOKEN_SCHEMA_INVALID`、`TOKEN_REVOKED`、`TOKEN_NOT_YET_VALID`（新）、`TOKEN_EXPIRED`、`TOKEN_USED_UP`、`TOKEN_FAMILY_MISMATCH`、`TOKEN_DEVICE_MISMATCH`、`TOKEN_ACTION_DENIED`。

### 2.5 `gateway.py` 變更

- `ROUTES` 新增：`guest_access`、`list_guest_tokens`、`revoke_guest_token`（皆 POST）。
- 新增 `GET /guest`。
- `run_cgi()` 多傳 `HTTP_HOST`、`REQUEST_SCHEME`（來自 `X-Forwarded-Proto` 或請求本身）給 CGI，供 `generate_guest_qr` 組網址。
- 既有路由、CORS、CGI 解析邏輯未改。

## 3. 門鈴／防拆推播

### 3.1 流程

```
ESP32 ── home/device/<mac>/event {"type": "doorbell"} ──► api-mqtt-bridge
                                                            │ 寫 audit_logs（DEVICE_EVENT，原本就有）
                                                            │ 已配對才轉發，同裝置同事件 30 秒冷卻
                                                            ▼
                                     home/security/gateway_<family_id>/alert
                                                            │
                                                            ▼
                                                      alert-service
                                    ├─ 有 anomaly_type → 記錄 UC4.4 安全異常
                                    ├─ Telegram / ntfy（背景執行緒）
                                    └─ app/user/<uid>/notifications（Admin、Member）
```

### 3.2 事件對應（`mqtt_topic_bridge.EVENT_ALERTS`）

| 事件 | severity | anomaly_type | 結果 |
|---|---|---|---|
| `doorbell` | LOW | — | 只推播 |
| `tamper_detected` | CRITICAL | `DEVICE_TAMPERING` | 記 UC4.4 異常 + 推播 |
| `alarm_triggered`（保險箱） | HIGH | — | 只推播 |

警報 payload：`request_id`（`EVT_<ms>_<device_id>`）、`device_id`、`family_id`、`event_type`、`severity`、`timestamp`（UTC）、`msg`、選填 `anomaly_type`。

冷卻 `ALERT_COOLDOWN_SEC`（預設 30）只擋推播，`audit_logs` 照寫。未配對裝置不發警報。

### 3.3 `alert_service.py` 變更

- 新增 Telegram / ntfy 推播（`common/push_notify.py`），在背景執行緒送出，不阻塞 MQTT 迴圈；放在查收件人之前，DB 失敗也推得出去。失敗只印 log、不重試。
- MQTT 連線從寫死 `1883` 改走共用 `mqtt_tls`（`MQTT_PORT` / `MQTT_USE_TLS` / `MQTT_CA_CERT`，預設 TLS 8883）。**原本正式環境 1883 已關，舊版 alert_service 其實連不上 broker。**
- 原本的 UC4.4 記錄與 App MQTT 通知邏輯未改。

### 3.4 `common/push_notify.py`

只用標準函式庫（`urllib`），不加相依套件。兩個通道各自用環境變數開關，一個失敗不影響另一個。ntfy 用 JSON 發布格式（中文標題放 header 會壞）。severity 對應 ntfy priority：LOW/MEDIUM=3、HIGH=4、CRITICAL=5。

目前是整個系統一個推播目的地，不分家庭／使用者（DB 沒存使用者的 chat_id / topic）。

## 4. 資料庫

`schema.sql` 只多一欄：

```sql
-- guest_tokens
valid_from DATETIME NULL,
```

**既有 DB 要手動補**（`schema.sql` 只在 MySQL 容器第一次啟動時執行）：

```bash
docker exec -i iot_mysql mysql -uroot -pdevroot123 devicemanagement < API/migrations/2026-10-24_guest_tokens_valid_from.sql
```

腳本可重複執行，欄位已存在就略過。

沒補的影響：只有「`start_time` 晚於現在」的 QR 會回 500；其餘功能正常（程式會偵測欄位是否存在）。

資料寫入面的變化：

| 表 | 變化 |
|---|---|
| `guest_tokens` | `generate_guest_qr` 改寫這張（原本不寫） |
| `users`、`user_families` | `generate_guest_qr` 不再寫入 |
| `audit_logs`、`control_commands` | `guest_token` 改存 `<redacted>` |
| `security_events` 等 UC4.4 表 | 防拆事件會經 alert-service 寫入（新來源） |
